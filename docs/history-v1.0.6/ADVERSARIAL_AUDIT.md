# 独立对抗式审计

**审计对象**：实际源码、知识库、工作流、测试，以及运行输出。
**不采信**：开发者自述、README 声明、文档承诺。
**审计时间**：2026-11-24

## 一、15 个元问题逐条回答

### 1. 是否真正解决了报奖工作的核心难题？

**部分解决。**
真正解决的是三件具体事：
- 规则准确性（487 条带页码原文，可追溯，13 奖项差异显式建模）
- 字数与格式合规（89 字段、60 处限制，可机械核验）
- 证据与归因的结构化审查（能抓出虚构来源、因果越级、口径错误）

未解决的是：**判断一个案例"创意是否打动人"**——这需要人类评委经验，脚本无能为力。
诚实说法：它替代了报奖负责人的"合规与逻辑审查"部分，不替代"专业品味"。

### 2. 是否只是给普通 AI 增加了专业角色描述？

**不是。** 证据：
- 446KB 规则库，每条有 SHA-256 与页码；模型无法"记得"这些，必须查询
- `validate_submission.py` 的 10 道门禁有真实判定逻辑，改状态字段无效（有测试证明）
- 字数、加权分、哈希、日期比较全部由代码完成，不依赖模型心算
- 但必须承认：**方法论部分（洞察分级、策略测试）仍是文字指导，靠模型自觉执行**

### 3. 官方规则是否存在缺失、误读或错误映射？

**存在，且已如实记录：**

| 问题 | 状态 |
|---|---|
| 汽车奖只列 8 条取消资格（无广告法） | 已如实记 8 条，未按九条补齐 |
| 7 个奖项无类别定义文件 | 标 MISSING，要求用户查官方 |
| 5 个奖项类别册 PARTIAL | 标 PARTIAL，禁止推测 |
| 场景奖两套权重（基础 + 户外子类） | 已建模为 `scoring_weights_override` |
| 全球化奖地域口径相反 | 已建模，有对抗测试 |

**潜在误读风险**：类别定义中 19 个类别共用定义（如 31/32），已标注
`definition_shared_with`，但"共用定义下如何区分"需模型按适用对象判断，脚本无法代劳。

### 4. 类别匹配是否退化为关键词匹配？

**脚本层是（有意为之），流程层不是。**

- `category_query.py --candidates` 只做召回，输出明确写"这是召回，不是结论"
- 初版用纯关键词时，搜"私域"命中"电竞新文创"（定义里含"私域"）。已修正：名称命中权重 100、
  定义命中权重 1
- `workflows/category-matching.md` 强制七维核验

**残余风险**：如果模型跳过七维核验直接用召回结果，就会退化为关键词匹配。
这是**流程纪律问题**，脚本无法强制。

### 5. 证据校验是否只是检查字段是否填写？

**不是。** 九项检查中至少五项是实质校验：

| 检查 | 实质内容 |
|---|---|
| E02 | 实际计算文件 SHA-256 与记录比对；文件不存在直接 P0 |
| E04 | 遍历 claims，验证 evidence_id 真实存在（抓悬空引用） |
| E05 | 逐字段比对主张与证据的 value/unit/period/scope |
| E07 | 检测同一主张绑定的多条证据数值是否互相矛盾 |
| E09 | 检测高保密证据是否标记为用于公开材料 |

有对抗测试证明 E02、E09 能真实触发。

### 6. 商业归因是否存在虚假专业性？

**这是本 Skill 最需警惕的地方，做了三层防护：**

1. **方法前提硬约束**：用 DID 必须有 `panel_data` + `parallel_trend_check`；无则报 A02 P1
2. **结论等级上限**：只有前后对比 → 最高 C 级；声称 A 级 → A05 P0
3. **14 类替代解释清单**：未排查过半则报 A03 P1

**残余风险**：脚本不知道用户填的 `confounders_addressed` 是否真的排查过。
它可以被填满 14 项而实际没做。这是**自报数据的固有局限**，只能靠审计时追问证据。

### 7. 模拟评审是否存在严重自我认同偏差？

**存在结构性风险，已用协议缓解：**

- 强制"先独立、再交叉、最后汇总"，禁止先算总分倒推
- 六视角各有专属关注点，V5/V6 被设计为"挑刺角色"
- 明确声明"单模型多视角，不是真实评委团"
- 禁止输出获奖概率

**未解决**：同一模型扮演六个角色，仍共享同一套偏好。真正的独立性做不到。
诚实说法：这是"结构化的自我批判"，不是"独立评审"。

### 8. 是否会迎合用户而放行低质量案例？

**脚本层不会，模型层有风险。**

- 状态由 `validate_submission.py` 算，用户说"帮我标成可提交"无效（有测试）
- 资格 BLOCKED 时后续全部阻断
- S12（看似成功无实效）场景被正确报警

**风险点**：`decimal` 类主观判断（"这个洞察够不够好"）可能因用户坚持而让步。
`SKILL.md` §8 列了必须说"不"的五种请求，但这是提示词约束，非机制约束。

### 9. 是否可通过改状态、分数或输入绕过硬性校验？

**已测四种绕过，全部失败：**

| 绕过方式 | 结果 |
|---|---|
| 案例 JSON 写 `"status":"READY_TO_SUBMIT"` | 无效，脚本重算 |
| 提高 `calculate_score.py` 分数 | 不参与门禁 |
| 删掉失败的必填项 | 字段表是外部基准，仍报缺失 |
| 改测试断言 | 能让测试绿，但门禁逻辑不变 |

**未测**：改 `references/*.json` 知识库（如把 4 改成 5 个类别上限）。
这确实能绕过——但那是篡改知识库，会在 `source_sha256` 与实际官方文件不符时暴露。
建议：生产使用时校验知识库哈希。

### 10. 用户资料是否存在泄露风险？

| 风险 | 处理 |
|---|---|
| 上传材料外传 | Skill 不联网、不上传；仅本地脚本处理 |
| 日志记录敏感数据 | 脚本不写日志文件；stdout 仅输出结论 |
| 机密进公开材料 | E09 检查 + G09 门禁 |
| 官方原件随包分发 | **未包含**，仅存文件名与哈希 |

**残余风险**：用户若把含客户数据的 case.json 提交到公开仓库，与本 Skill 无关但需提醒。

### 11. 文件规模与 Token 消耗是否合理？

| 项 | 值 | 评价 |
|---|---|---|
| 文件数 | 42 | 合理，每个都有明确用途 |
| 知识库 | 666 KB | 大，但**按需查询不全读** |
| SKILL.md | 8 KB | 适中 |
| 单次任务典型加载 | SKILL.md + 1–2 reference ≈ 15–30 KB | 合理 |

**优化点**：`annual-rules-2026.json` 446KB 是最大文件。
已通过 `rule_query.py --type` 按需切片，避免全量入上下文。

### 12. 真实模型使用时是否可靠执行？

**未验证。** 这是本版本最大的未证明项。

- 无独立模型调用能力，无法做 A/B/C 对照
- 未在真实 WorkBuddy 宿主内跑触发测试
- 不知道模型是否会真的按 SKILL.md 的路由表选择工作流

**已做的缓解**：SKILL.md 结构强约束（任务路由表、必须跑脚本、禁止事项清单），
但"写了规则"不等于"遵守规则"。

### 13. 是否存在代码通过测试但业务判断错误？

**发现并修复 4 处：**

| 缺陷 | 性质 |
|---|---|
| 归因 RANK 比较方向反 | A 最强被当最弱 → 所有归因判断反向 |
| 115 新品年龄未核算 | 只看有无日期，不看差多少月 |
| 91/92 主体错投未拦 | 缺规则分支 |
| GMV 冒充销售额未检出 | 缺规则 |

这些都是"测试全绿但业务判断错"的典型。修复后加了对应回归测试。

**残余**：语义类判断无法用脚本验证对错，只能靠人审。

### 14. 普通广告公司员工能否直接使用？

**需要一定专业基础。**

- 能用：跑脚本查规则、查字数、跑资格校验（命令行即可）
- 需指导：如何组织 case.json（有模板，但字段多）
- 门槛：需理解"证据登记""归因等级"这些概念才能填对

**改进建议**：提供一个交互式 `case_builder.py` 引导填写（本版未做）。

### 15. 当前版本是否真实具备商业使用价值？

**具备"辅助审查"价值，不具备"独立完成报奖"价值。**

| 场景 | 可用性 |
|---|---|
| 查规则、查类别、查字数 | ✅ 直接可用 |
| 资格预检 | ✅ 直接可用，能省掉取消资格风险 |
| 数据口径与归因审查 | ✅ 直接可用，能抓出常见硬伤 |
| 证据审计 | ✅ 可用（前提是有原始材料） |
| 写参赛表正文 | ⚠️ 需专业人审，模型只能给结构和初稿 |
| 判断能否获奖 | ❌ 不做，也不该做 |

## 四、诚实结论

**这个 Skill 在"规则准确性、合规拦截、数据审查"三件事上是有真实能力的，
因为它们被代码化了，有 63 项测试证明。**

**在"创意品味、洞察深度、策略独创性"三件事上，它只是提供了专业框架和检查清单，
实际质量取决于使用者与模型的专业水平。**

**它不能保证获奖，也不应该被这样使用。** 它的价值在于：
让真正有效的案例不被形式问题埋没，让无效的案例被及早识别。
