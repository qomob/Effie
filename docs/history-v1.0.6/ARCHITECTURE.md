# 架构说明

## 设计目标

不是"给普通大模型加一段专业人设"，而是把**可机械验证的业务规则**交给代码，
只在代码做不到的地方用模型判断。这条边界决定了全部架构。

## 核心分层

```
SKILL.md                    入口：任务路由 + 铁律 + 加载纪律
├── references/             结构化知识 + 专业方法论（渐进加载）
│   ├── annual-rules-2026.json      487 条规则（13 奖项，每条带页码+原文）
│   ├── categories-2026.json        134 类别（28 行业 + 106 专项 + 6 赛道）
│   ├── entry-fields-2026.json      89 字段（60 处字数限制）
│   ├── official-source-registry.json  81 份文件 SHA-256
│   ├── award-index.md              ★ 奖项差异表（最易错处）
│   └── *.md                        专业方法论 6 篇
├── workflows/              12 种任务流程（按意图路由，不强制全跑）
├── scripts/                13 个确定性校验器
├── schemas/                8 个 JSON Schema
├── templates/              7 个交付模板
├── examples/               合成示例 + 走查
└── tests/                  63 项真实测试
```

## 确定性与 AI 判断的边界（核心设计决策）

| 交给代码 | 为什么 | 交给模型 | 为什么 |
|---|---|---|---|
| 字数统计 | 可数，且心算必错 | 洞察质量 | 需语义判断 |
| 日期窗口 | 可比较 | 策略排他性 | 需品类知识 |
| 类别数量限制 | 可计数 | 类别语义适配 | 需理解定义 |
| 加权分计算 | 权重来自规则库 | 归因合理性 | 需方法学判断 |
| 文件哈希 | 可计算 | 叙事结构 | 需写作能力 |
| 主张-证据绑定 | 可遍历 | 案例价值诊断 | 需综合权衡 |
| 数值/周期一致性 | 可比较 | 评委视角挑错 | 需角色切换 |
| 状态机 | 可判定 | 差异化叙事 | 需创意 |

**关键原则**：AI 自我声明"我检查过了"不算验证。所有"通过"必须来自脚本退出码。

## 为什么规则存 JSON 而不是写进提示词

1. **可追溯**：每条规则带 `source_document + source_page + source_quote + sha256`
2. **可校验**：脚本能算出"使用这条规则时引用了哪一页"
3. **可维护**：官方更新时改 JSON，不用改提示词
4. **省 token**：446KB 规则库按需查询，不必全读进上下文
5. **防幻觉**：模型不能"记得"一条规则，必须查到

## 为什么奖项差异必须显式建模

抽样 13 份手册发现三处硬冲突：

| 维度 | 冲突 |
|---|---|
| 评分权重 | 多数 23.3/23.3/23.3/30；GLOBAL 与 SCENARIO 是 15/25/30/30；SCENARIO 户外子类 15/30/30/25 |
| 地域口径 | 12 个要求大中华区；GLOBAL 要求**海外** |
| 材料体系 | 多数 视频+平面；GLOBAL/PRA/DIA 是 案例阐述PDF+投放素材 |

如果按"主流值"做默认，会在这 3 个奖项上系统性出错。因此规则按 `award_id` 分区存储，
且 `rule_query.py` 强制指定奖项，不提供"全局默认值"。

## 为什么不用关键词匹配做类别推荐

关键词匹配的实际失败（本项目复现）：

- 搜"私域"→ 命中"电竞新文创"（其定义里出现"私域"二字）
- 搜"公益"→ 同时命中"社会公益-品牌"和"环境公益"（资质要求完全不同）

因此 `category_query.py` 只做**候选召回**，输出明确标注"这不是匹配结论"。
真正的匹配要求七维核验（资格/商业问题/机制/成果/证据/竞争力/组合合规），
由模型在 workflow 引导下完成。

## 数据抽取的工程难点（真实记录）

源 PDF 的 CJK 字体是 Identity-H 编码 + **伪造的 ToUnicode 映射**：

| 工具 | 结果 |
|---|---|
| pdftotext -layout | 中文全丢，只剩英文数字 |
| pdfminer.six | 输出 `(cid:12345)` 占位符 |
| pypdf | 输出乱码（䎃剢1傈荛） |

解决方案：`pdftoppm -r 200` 渲染 + macOS Vision OCR（`zh-Hans`）。
27/81 份文件必须 OCR，共恢复 57.9 万汉字。

**这直接决定了一条设计**：知识库里每条规则都带页码，因为 OCR 文本无法用字符偏移可靠定位，
页码是唯一稳定的锚点。

## 失败与降级设计

| 情况 | 行为 |
|---|---|
| 规则缺失 | 返回 MISSING，不给默认值；资格判定降为 UNKNOWN |
| 类别册 PARTIAL | 明确提示"需核对官方文件"，不推测缺失类别 |
| 无脚本环境 | 退化为人工核算，但必须声明"未经脚本校验" |
| 无文件读写 | 只在对话内交付 |
| 年度不覆盖 | 拒绝用其它年度规则判定 |

## 规模控制

| 项 | 值 |
|---|---|
| 文件数 | 73（含 5 个 JSON 知识库） |
| 知识库体积 | 约 700 KB |
| SKILL.md | 约 8 KB（不含知识库） |
| 首次加载 | SKILL.md + 按需 1–2 个 reference |
| 测试 | 72 项，约 25 秒 |

不一味增加文件：没有真实用途的文档一律不建（见 README 的取舍说明）。
