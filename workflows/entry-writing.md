# 工作流：案例叙事引擎（entry-writing）

**对应模块**：M08　**触发**："帮我写参赛表""帮我改这份参赛表"

## 叙事主干（必须成立的因果链）

```
商业挑战 → 营销目标 → 消费者洞察 → 策略选择 → 核心创意
        → 市场执行 → 行为变化 → 商业成果 → 营销贡献
```

每一环必须回答"为什么"：

| 环节 | 必答问题 | 写不好会怎样 |
|---|---|---|
| 挑战 | 这个商业问题为什么难？ | 没有参照系，后面全无意义 |
| 目标 | 为什么定这个目标？品类基准多少？ | 目标像事后倒推 |
| 洞察 | 为什么这个洞察有价值？ | 沦为常识 |
| 策略 | 为什么这样选而不是别的？ | 策略不排他 |
| 创意 | 为什么这个创意能解决问题？ | 创意与策略两张皮 |
| 执行 | 执行如何体现策略？ | 变成渠道清单 |
| 成果 | 目标真的实现了吗？ | 成果与目标不对应 |
| 贡献 | 营销贡献了什么？ | 相关性冒充因果 |

## 写作流程

### 阶段一：字段规划（先算字数，再动笔）

```bash
python3 scripts/field_query.py --summary
python3 scripts/field_query.py --part 1
```

主奖项四部分字数上限（含全部选填目标）：

| 部分 | 上限合计 | 关键字段 |
|---|---|---|
| 执行摘要 | 450 | 5×50 + 200 |
| 第一部分 | 3490 | 1.1(800) + 目标×(60+150+60) |
| 第二部分 | 2200 | 2.1(600)+2.2(600)+2.3(400) |
| 第三部分 | 2000 | 3.1(600)+3.2(600)+3.3(800)+投资概览(600) |
| 第四部分 | 3570 | 4.1(700)+成果对×(60+150)+4.2(400) |

> 若只设 1 个营销目标 + 1 个战役目标，第一部分可省约 630 字配额——
> **少设目标不是损失，是聚焦**。目标越多，每个都要有对应成果。

### 阶段二：逐字段写作规范

**1.1 挑战（≤800 字）**
```
品牌是谁 + 品类状况（含数据） → 具体结构性障碍 → 为什么难
必须含：竞品支出/地位、品类基准、市场趋势
禁止：只写"竞争激烈"、用行业黑话不解释
```

**1.2 目标（每个 60+150+60）**
```
概述："商业目标：份额从18.4%提升至20%以上"
依据："品类均值增长12%，头部竞品+9%，故+2pt份额属挑战性目标"
衡量："尼尔森零售监测，月度，2025.03–06"
标签：从官方下拉选（不得自创）
```

**2.1 受众（≤600）** → 分层：核心/扩展/辐射，每层与生意挂钩
**2.2 洞察（≤600）** → 现象 → 张力 → 机制 → 所以品牌可以做什么
**2.3 策略（≤400）** → 一句话策略内核 + 如何把挑战转为解
**3.1 激活（≤600）** → 全部组成部分（传播/促销/CRM/体验/价格）
**3.2 创意（≤600）** → Slogan/CTA/形式选择 + 执行中的优化调整
**3.3 渠道（≤800）** → 为什么这些渠道 + 如何协同 + 预算如何调配
**4.1 成果（≤700）** → 逐目标对应 + 品类/历史对照 + 对生意的意义
**4.2 归因（≤400）** → 主动列出替代因素及量化影响

### 阶段三：事实分级标注（每段强制）

写的时候同步打标。交付给用户时可保留标记，也可转成脚注，但**内部必须留档**。

```
"活动期间新客占比从34%升至51%[FACT][脚注1]"        ← 有证据
"品类同期仅增长12%，品牌增长21%[CALC][脚注1,2]"     ← 计算
"我们认为这主要来自对'周四情绪出口'的准确捕捉[INFERENCE]"
"建议补一次地域对照实验以强化因果[RECOMMENDATION]"
"目标设定时间无书面记录[UNKNOWN]"
```

### 阶段四：三遍检查

**第一遍：字数与结构**
```bash
python3 scripts/check_word_limits.py --case case.json
```
超限只删修饰语，不删数据与因果论证。

**第二遍：数据与归因**
```bash
python3 scripts/validate_metrics.py --file metrics.json
python3 scripts/audit_attribution.py --file attribution.json
python3 scripts/verify_evidence.py --file evidence.json --base-dir ./materials
```

**第三遍：一致性（多类别时）**
```bash
python3 scripts/check_consistency.py --versions v_main.json v_cat46.json
```

## 已有参赛表优化模式

1. **先留原件**：把用户原稿完整保存，不改动
2. **逐字段体检表**：

| 字段 | 现状问题 | 严重度 | 改法 | 改后字数 |
|---|---|---|---|---|
| 1.1 | 无品类基准 | P1 | 补品类增速与竞品份额 | 742/800 |
| 2.2 | 洞察是现象描述 | P1 | 下沉到机制层 | 588/600 |

3. **出修订稿 + 变更记录**（哪句改了、为什么改）
4. **不改变事实**：只能改表达，不能改数字

## 严禁

| 严禁 | 因为 |
|---|---|
| 事后编造营销目标 | 评委能看出目标与成果同构 |
| 编造消费者洞察 | 洞察不可验证但会露馅 |
| 编造策略制定过程 | 团队访谈一问即穿 |
| 把建议写成已执行 | 严重诚信问题 |
| 编造第三方评价/奖项 | 可查证 |
| 虚构来源 | 取消资格条款 |

## 未启动项目的处理

用户想报还没做的项目：
- 可以出"未来方案"，但必须标 `PROPOSED`
- 不得描述为已实施
- 不得用于当前年度正式参赛（资格 BLOCKED）
- 引导走 `evidence-planning.md`

## 语气与风格

- 简洁 > 华丽。评委一天看 20 件。
- 每个数字后面给对照。
- 术语首次出现要解释（评委可能不在你的品类）。
- 不用"赋能、抓手、闭环、引爆、破圈"这类无信息量词。
- 英文术语保留原文 + 中文解释。
